# Header dropdown review

> Historical initial review. Superseded by [the completed follow-up report](HEADER-DROPDOWN-FOLLOWUP.md), which records the backend fixes, corrected response mappings, restored CMS content, and final verification limits.

Review date: 17 November 2026. Scope: all 25 dropdown destinations and the two adjacent Acts & Rules / Policies pages (27 pages). Existing uncommitted header work was preserved and corrected in place. No backend APIs, database records, access rules, or authenticated workflows were invented or changed.

## Verification result

- All 27 destinations resolve to their intended React pages. Desktop, tablet, and mobile checks cover 1440, 768, and 375 px widths.
- The local backend is running. Its public JSON endpoints exist in Java source, but anonymous requests redirect to `/mpmsme/website/login`, which returns HTTP 200 HTML. They are **not live-data verified**. This is now an explicit error state, not an empty successful result.
- CMS content is read from actual server pages. Page sources are selected from the live CMS menu, using its original backend URL; frontend aliases are not used as invented CMS slugs.
- Real CMS orders are displayed. The CMS itself includes records named “circular test” and “order test”; these are backend records, not frontend fixtures. They need CMS-owner review. This task did not delete database content.
- Five published CMS destinations have empty bodies. Other new informational sections have no confirmed CMS source. Both cases display an unavailable message without fabricated text, downloads, metrics, or policy benefits.

## Shared fixes and validation

- Fixed conditional React hooks by separating route dispatch from the CMS component. Removed unrelated aliases that sent events/gallery/useful links to policy/land pages.
- Removed broad landing-page fallbacks that silently converted unknown API/download/detail URLs into unrelated frontend pages. Confirmed page aliases remain available.
- Shared concurrent reads prevent duplicate requests on StrictMode mounts; completed requests are not permanently cached. Added timeouts, explicit JSON/envelope checks, loading/error/empty states, retry, pagination and stale-response protection.
- Removed unsupported promotional numbers from menu metadata. Static navigation labels, branding, UI copy and a 25-row page size remain intentionally hardcoded; these are not business data.
- Fixed nested main landmarks, page titles, CMS table whitespace warnings, empty CMS containers, mobile header clipping and oversized page headings. Native print and accessible dropdown behavior remain available.
- `npm.cmd run build`: passes. Existing large-bundle, legacy font/watermark and legacy CSS pseudo-class warnings remain.
- Targeted `oxlint`: no errors or unused/undefined-symbol warnings. Three existing effect-state warnings remain in HomePage, legacyWebsite and PublicContentPage.
- `scripts/check-header-browser.mjs`: all 27 destinations, three widths, CMS-to-dedicated navigation/back, Escape dropdown handling; no runtime exceptions or console errors in the completed clean pass. Screenshots and details are in `artifacts/header-pages/`.
- `scripts/check-header-contract.mjs`: isolated test responses verified actual field mapping, zero values, server pagination, request deduplication, malformed envelopes, empty results, HTTP errors/retry, date parameters and application status. These fixtures are test-only and are never shipped or displayed by the application.
- `scripts/check-header-api.mjs`: live endpoint/CMS HTTP checks. Test artifacts contain endpoint metadata, not applicant records.

## Limits and required follow-up

This is not a claim that all production services or CMS downloads work. The public JSON access restriction, missing/empty CMS content, and inaccessible CMS document hosts remain blocking dependencies. Backend owners should provide an intentionally public, appropriately limited response contract rather than exposing the existing full case/applicant beans wholesale. No security rules were relaxed here.

Authenticated application submissions, payments and other mutations were not exercised. The existing protected routes were checked as navigation targets and their implementation was preserved. Labels/content still require a translation review for newly created page bodies; existing Hindi navigation and locale-driven CMS reads are retained.

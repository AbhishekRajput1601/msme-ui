# Header dropdown review: final follow-up

Updated 18 November 2026. Scope: 25 dropdown destinations plus Acts & Rules and Policies. Changes are in the local frontend/backend workspace; production deployment was not performed. This report supersedes HEADER-DROPDOWN-REVIEW.md, including its earlier access restrictions and empty-CMS findings.

## Outcome

The packaged backend verified on 17 November returned real JSON from existing public endpoints instead of login HTML. CMS content that appeared empty was present in the database: the DAO discarded the stored procedure result. Named-column mapping restores that content in both languages. No HTTP endpoints, database content, policy benefits, contacts, or document URLs were invented.

**Current runtime limitation (18 November):** port 8080 is now owned by an existing IDE Java process (PID 11876). Its developed/undeveloped land, case-list and archive endpoints return HTTP 500 with `Unresolved compilation problems: PublicLandingData cannot be resolved`. This differs from the successfully built/tested WAR. The IDE workspace must refresh/rebuild the common module and dependent modules and restart its server. The attempted standalone WAR launch could not bind the occupied port. This runtime problem is pending; it is not a successful live API verification today. Industrial areas, collector rates and CMS endpoints still return HTTP 200. The UI displays explicit error/Retry states for failed requests.

Pages without a usable matching CMS source show **Currently no data available.**, as requested. API failures remain error/retry states, rather than being disguised as empty successful results. Static navigation labels, UI instructions, branding and pagination sizes remain intentional constants; business data comes from the backend.

## Shared fixes and backend safeguards

- Fixed conditional React hooks and missing imports. Removed unrelated route aliases and broad redirects that converted unknown API/download paths into unrelated pages. Preserved confirmed legacy aliases.
- Added shared in-flight request deduplication, 20-second timeout, content-type/envelope validation, loading/error/retry/empty states, stale-result protection, pagination and date validation. Test fixtures exist only in verification scripts.
- Fixed mobile header wrapping, title sizing, breadcrumbs, table scrolling and nested main landmarks. CMS tables no longer generate whitespace nesting warnings; accordion content uses native details elements.
- Exact GET-only access rules cover six existing public reads. Anonymous land/case responses use explicit whitelists; application status uses only application number and status. Authenticated original responses remain available. Pagination is clamped to 1–200 rows and nonnegative offsets.
- CMS DAO uses the existing parameterized stored procedure and named result columns, preserving the transaction connection. No database writes were made.

Five private-detail/write probes remained HTTP 302 redirects to authentication.
